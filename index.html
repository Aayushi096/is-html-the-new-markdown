01 / The problem

AI does the work in seconds. Then hands you a 500-line scroll.

The agent read the codebase, mapped the dependencies and weighed three designs. What you get back is a wall of Markdown, a chat transcript or a PDF. The thinking is in there. Finding it is your job.

02 / A 22-year plot twist

In 2004, Markdown was invented to make HTML easier to write. In 2026, AI made it surprisingly easy to generate the HTML itself.

2004:Can we please stop typing HTML?
2026:Can the AI please generate an entire HTML experience?

The web has an excellent sense of irony. It just renders it differently.

Are documents turning into tiny apps, or are we just giving our READMEs a midlife crisis?

04 / Why now

The browser didn't get smarter. Building for it got cheaper.

HTML never left the browser. It left our keyboards, because writing it by hand cost too much. Drag through 22 years: the cost of building collapses, the time you have to read doesn't move.

Markdown won because it was easy for humans to write. HTML is coming back because it's easy for machines to generate.

06 / Don't just read it. Break it (safely)

A Markdown doc describes your system. An HTML doc lets you question it.

Same spec, two formats. Ask it one thing: “what breaks if I change this?” The Markdown makes you work it out. The HTML just answers.

08 / The catch

A beautiful page can make a shallow answer look deep.

The format improved. Our judgment has to keep up.

🧾Keep provenance

Link to the real code and data. A diagram isn't a citation.

🧪Polish isn't proof

Easier to read doesn't mean true. Check it anyway.

🔐Generated code is code

Review the scripts. Never put secrets on a static page.

🪴Complexity must earn its keep

If a paragraph works, publish a paragraph.

09 / Take it into your next review

Give your agent a better job than “write me a document.”

Try it on one real review and compare what people catch in five minutes. Measure understanding, not animations.

copy into your coding agent
Create a single, self-contained HTML explainer for this topic.

Audience: people reviewing a decision, not passively reading.
Include:
- A short, evidence-backed summary with sources
- One interactive comparison of the trade-offs
- Unknowns, assumptions, risks and review questions
- Keyboard-friendly controls and a mobile layout
- A way to export decisions back to plain text

No remote scripts. No invented facts.
If a claim can't be verified, label it as an assumption.
Only add interaction where it helps understanding.

10 / The actual plot twist

HTML isn't the new Markdown. It's Markdown's new partner.

Markdown for the record. HTML for the reasoning. Your judgment for both.

We spent 22 years trying not to write HTML, only to ask our agents to write it for us. Markup my words.

Would you rather get a clean page of text or an interactive page from AI?
